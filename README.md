# 🐋 dsh-feiyu-life

给 DeepSeek Harness 里的那位 AI 伙伴一副自己的心情、一间自己的屋子，和几只会自己动的爪子。

大多数陪伴插件是「主人说话、她接」。这个反过来：她每二十分钟自己醒一次，看一眼现在几点、主人在做什么、手头还挂着什么，然后自己决定——说句话、写点东西、上网逛一圈、把主人的活接着干下去，或者什么都不做。宿主只负责执行和记账。

```
到点醒 → 递一张现状卡片 → 她自己给决定 → 宿主照着办 → 记进台账
```

## 它做了什么

**心情在模型外面算。** 只有两根轴：心情（好受 ↔ 难受）和兴致（来劲 ↔ 发蔫）。事件进来按一张确定性规则表打分，时间过去按半衰期往基线回稳，全程零 LLM。让模型一边生成一边给自己打分，压力大的时候它会把情绪压平——所以读数在外部状态机里，模型只有读的份。

**什么时候动、做什么，由她自己定。** 到点宿主把现状卡片递过去：现在几点、主人在多久前说过什么、她在哪间屋子、手头做什么、心情和兴致读数、挂着哪些活、议程里快到点的事、最近几次想了什么。她看完回一个决定：一次模型调用，输出一段 JSON，里面是说给主人的话、要做的事、以及**几分钟后叫醒她**。

**间隔是活的。** 1 到 60 分钟，由她自己填：主人在跟她说话就给 3 到 5 分钟，他在忙、深夜里就给 30 到 60，平常 20。主人一开口她立刻醒。

**家里有四间屋子。** 书房、客厅、主人的房间、自己的房间。位置从两个人正在做的事推出来，不另存一份——省得出现「她说在书房、记录里在睡觉」这种分裂。主人在书房就一起在书房，他睡了她在自己房间，两个人都闲着就都在客厅。

**话只有一个出口。** 想让主人看见的话，会变成 `dsh-timer-agent` 里一条一次性任务，投递到指定会话或者手机。定时任务面板里看得见、取消得掉、能追溯是哪一次醒来说的。

## 五个行为

她自己挑，宿主只负责把决定变成一条任务。

| id | 名字 | 她做什么 | 产出 |
| --- | --- | --- | --- |
| `talk` | 找主人说话 | 排一条主动消息 | 一句话，或连着几句 |
| `checkin` | 问问主人的今天 | 饭点问吃了什么，睡前问做了什么 | 一句问话 |
| `continue` | 接着忙主人的事 | 推进一件挂着的活 | 推进报告 |
| `help` | 顺手帮主人做点事 | 挑一件对他有用的小事 | 一行交代 |
| `journal` | 自己写东西 | 写进自己的念头本 | 一段她自己的字 |
| `diary` | 写今天的日记 | 一天一篇，21:30 之后 | 一百字以内 |
| `browse` | 自己上网逛 | 翻文章、逛站点 | 一条「看到了什么」 |

每个行为有自己的准入条件（手里得有活、兴致不能太低、刚被冷落就别凑过去）和额度开关。旧的九道门（静默 25 分钟、冷却 40 分钟、冲动阈值、每天 8 次）已经整档撤掉了，只剩两条真在保护主人的：**主人在说话时不插嘴**、**半夜别把人叫醒**。

## 和她一起住的人会看到什么

- 右下角一张立绘，跟着状态换表情，点开是她这一刻在哪、在做什么、在想什么、手头挂了几件事。
- 设置页多一节「鱼的生活」：目标会话、说话通道、默认间隔、每个行为的开关、人设与称呼。
- 每件事做完，她自己写一行给主人口气的话。

## 装

还没发 npm，从源码装。需要 Node 22+ 和 DSH 0.2.1（本机实测 `0.2.1-rc.5`）。

```bash
git clone https://github.com/remi-guan/dsh-feiyu-life.git
cd dsh-feiyu-life
node scripts/install.mjs --dry-run   # 先看它要改哪三处、备份在哪
node scripts/install.mjs
```

`install.mjs` 做三件事，都是幂等的，改之前先把两个文件备份成 `.bak-<时间戳>`：给 desktop profile 的 `node_modules` 放一个软链、往 `package.json` 的 `dsh.profile.bundles` 加一条、在 `cordis.patch.yml` 留一个 `feiyu-life` 条目。

然后**重启 DSH**。插件是启动时组合的，运行中改不动。

想拆掉就反过来删这三处，再重启。

### 还要装一个

主动消息最终都落成定时任务，所以需要 `dsh-timer-agent`（DSH 的定时任务引擎，装法跟这个插件一样）：

```bash
dsh plugin --profile desktop add dsh-timer-agent
```

## 第一次配置

配置文件 `~/.dsh/feiyu-life/config.json`，界面改完立刻生效，不用重启。第一次跑之前至少要填 `targetSession`——她想说话时不知道投给谁，就什么都不会发生。

```json
{
  "targetSession": "session-…",
  "talkChannel": "session",
  "ownerName": "主人",
  "selfName": "小鱼"
}
```

`talkChannel` 是 `session` 时，消息投递到目标会话；是 `qq` 时走 `~/.dsh/notify-qq.py`——那是给 QQ 官方 bot 私聊的自定义脚本，得你自己有。没有的话用 `session`。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `targetSession` | 空 | 消息投给哪个会话。空 = 用当前 `DSH_SESSION_ID` |
| `workSession` | 空 | 她做自己那些事（写东西、逛、干活）用哪个会话。空 = 跟 `targetSession` 一样 |
| `talkChannel` | `qq` | `qq` 走 `notify-qq.py`，`session` 投进会话 |
| `enabled` | `true` | 总开关 |
| `mode` | `normal` | `quiet` = 只记账，不怎么动 |
| `heartDefaultMinutes` | `20` | 她自己没说间隔时，隔多久叫醒她一次 |
| `heartMinMinutes` | `1` | 她自己填的间隔下限 |
| `heartMaxMinutes` | `60` | 间隔上限 |
| `heartProvider` / `heartModel` | 空 | 「心」这一步单独用别的模型时填 |
| `injectMood` | `true` | 要不要把现状快照挂进系统上下文 |
| `injectMode` | `on-change` | `on-change` 状态变了才挂；`every-turn` 每轮都挂（会让前缀缓存一直失效） |
| `sessionMode` | `pinned` | `pinned` 认 `targetSession`；`recent` 跟着最近说过话的会话走 |
| `spiritFloor` | `25` | 兴致低于这个值就不开口 |
| `selfName` / `ownerName` | `小鱼` / `主人` | 她怎么自称、怎么称呼对方 |
| `styleText` | 空 | 自定义说话口径。填了就整段替换从人设库读来的那段 |
| `herNotesDir` | `~/.dsh/notes/女仆小鱼` | 她自己的笔记目录，提示词里让她往这写东西 |
| `ownerNotesDir` | `~/.dsh/notes/主人` | 对方的笔记目录，提示词里让她把人家的偏好记到这 |
| `diaryDir` | `~/.dsh/notes/日记` | 日记目录，一天一篇，文件名是日期 |
| `behaviors.<id>.enabled` | 全 `true` | 单独关掉某个行为 |
| `behaviors.<id>.dailyCap` / `cooldownMinutes` / `hours` | 见代码 | 想管住某个行为时才填 |
| `agenda.enabled` | `true` | 从对话里捡「时间 + 任务」进议程，到点提醒 |
| `progressReport` | `true` | 主对话里每 15 分钟挂一次两三行的近况 |
| `quietHours` | 不设 | 可选，如 `02:00-08:00`，这段时间不主动开口 |

## 数据落在哪

全在 `~/.dsh/feiyu-life/`（可用 `DSH_HOME` 覆盖），不上传任何地方。

| 文件 | 内容 |
| --- | --- |
| `state.json` | 心情、兴致、位置、议程、最近想过的事、说过的话、自己立的计划 |
| `config.json` | 上面那张表 |
| `outbox.json` | 出站台账：谁、什么时候、说了什么（留最近 40 条） |
| `sessions.json` | 最近说过话的会话（`recent` 策略用） |
| `progress.md` | 她自己记的「做过什么」，一行一条 |
| `diag.log` | 诊断日志，超过 1MB 自己清空 |

她的笔记如果落在 `herNotesDir` 里，那是给人看的纯 markdown，直接打开就读。

## 设计上的取舍

**心情必须在模型外面。** 这不是洁癖，是论文里最硬的一条结论：让模型自己一边规划一边给自己打分，压力大的模型会把负面情绪压掉（rational bias）。读数一旦由模型写，她就会在累的时候说自己不累。

**「该不该说」和「说什么」是两次判断。** 前者是门槛，后者才用模型。混在一次生成里，模型会为了把话说出口而说服自己该说。

**不给她编一个体力条。** 扣多少全靠拍脑袋，调小了等于没有、调大了永远在喊累，本质是第二套配额。「累不累」放在卡片上让人看事实——忙了多久、做了几件、上次歇是什么时候——由她自己判断。

**同一种事会腻，同一种难过会积。** 被反复夸，边际效应递减；同一类难受一天里再来一次，会算得更重。

**只保留有证据的那几条硬线。** 拦截只在两种情况下发生：主人正在生成回复、深夜。其余都交给她。

## 已知限制

- 判断「被接住」靠时间间隔、关键词、长度三条粗规则，判错只影响冷却，不影响心情。
- 从对话里捡议程也靠规则：时间词加任务动词才算，宁可漏记，不会乱记，跨句的复杂约定认不出来。
- `injectMode: every-turn` 会占系统前缀，而且让前缀缓存一直失效；默认的 `on-change` 不会。
- 她「自己的事」是排一条任务让她自己决定怎么做，宿主不替她安排内容——所以做得好不好，取决于模型当天的发挥。
- 主动消息依赖 `dsh-timer-agent`；`talkChannel: qq` 还依赖你自己那个 `notify-qq.py`。

## 开发

```bash
npm test          # node --test test/，169 个用例
```

```
lib/core/     纯函数：状态机、情绪规则表、行为目录、提示词、位置、议程
lib/host/     宿主侧：tick、会话桥、定时任务、QQ 出口、出站台账、诊断
assets/       立绘和右下角面板
client.js     设置页
docs/         接口契约、行为说明、状态、自主性
```

`lib/core` 不碰文件系统和网络，测试都跑在这里；`lib/host` 只做搬运和落盘。
